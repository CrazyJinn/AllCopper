# 需求传达

接收上游文档更新，逐级向下传达变更，确保各环节文档同步更新。

## 输入

| 文件 | 必需 | 说明 |
|-----|-----|-----|
| 修改内容说明 | 是 | 描述本次修改的内容和意图 |

## 输出

```
99_变更管理/
└── YYYY-MM-DD_变更标题/
    ├── 变更记录.md      # 变更历史记录
    └── 变更通知.md      # 影响分析和待更新项
```

## 文档层级结构

```
00_init/                    # 第1层：初始设定
├── 世界设定.md
├── 剧本大纲.md
└── 游戏概览.md

01_需求文档/                # 第2层：需求文档
├── 游戏基本信息.md
├── 角色需求.md
├── 场景需求.md
├── 音频需求.md
└── 代码需求.md

02_角色设计/                # 第3层：角色设计
├── 角色设计总览.md
├── 主角/
├── NPC/
└── 怪物/

03_场景设计/                # 第3层：场景设计
├── 场景设计总览.md
├── 室外场景/
└── 室内场景/
```

## 工作流程

### 步骤1：接收更新
- 接收用户提供的修改内容说明

### 步骤2：识别变更类型，更新00_init
根据修改内容判断属于哪个方面，更新 `00_init/` 中对应文件：

| 变更类型 | 更新文件 |
|---------|---------|
| 世界观/背景设定/势力/历史 | `00_init/世界设定.md` |
| 故事线/章节/剧情发展 | `00_init/剧本大纲.md` |
| 玩法/系统/核心机制 | `00_init/游戏概览.md` |

### 步骤3：识别变更影响，更新01_需求文档
根据00_init的变更，判断需要更新 `01_需求文档/` 中哪些文件：

| 上游变更 | 下游更新 |
|---------|---------|
| 世界设定.md | 游戏基本信息.md, 角色需求.md, 场景需求.md, 音频需求.md |
| 剧本大纲.md | 角色需求.md, 场景需求.md, 音频需求.md, 代码需求.md |
| 游戏概览.md | 代码需求.md, 游戏基本信息.md |

### 步骤4：通知下游环节
根据01_需求文档的变更，判断需要通知哪些下游环节更新：

| 需求文档变更 | 通知下游 |
|-------------|---------|
| 角色需求.md | `02_角色设计/` - 重新生成受影响角色的提示词 |
| 场景需求.md | `03_场景设计/` - 重新生成受影响场景的提示词 |
| 音频需求.md | 音频制作环节 |
| 代码需求.md | 代码实现环节 |
