# 需求分析指南

指导如何从代码需求文档中提取信息并设计系统架构方案。

## 分析步骤

### 1. 提取系统清单

从代码需求文档中提取所有系统，按优先级（P0/P1）分类：

- **P0 核心系统**：角色控制、战斗、受伤判定、对话、背包、战斗场景、经济、怪物AI
- **P1 扩展系统**：关卡类型、存档、音频管理、资源管理
- **UI系统**：按优先级排序的所有 UI 模块

### 2. 设计模块依赖关系

为每个系统确定：
- 上游依赖（需要哪些其他系统的输出）
- 下游输出（本系统为哪些系统提供数据）
- 使用 mermaid 绘制依赖图

### 3. 定义接口协议

每个系统需定义：

```
系统名: <名称>
输入:
  - <依赖数据1>: <数据类型>
  - <依赖数据2>: <数据类型>
输出:
  - <产出数据1>: <数据类型>
  - <产出数据2>: <数据类型>
信号/事件:
  - <signal_name>: <触发条件> → <监听方>
```

### 4. 数据结构设计

基于需求文档中的数据结构需求，设计 Godot 资源格式：

- 角色数据 → `CharacterData` Resource
- 物品数据 → `ItemData` Resource
- 怪物数据 → `EnemyData` Resource
- 对话数据 → `DialogData` Resource

每个数据结构需明确字段名、类型、默认值、验证规则。

### 5. 架构模式选择

| 模式 | 适用场景 | 本项目应用 |
|------|---------|-----------|
| 单例 (Autoload) | 全局状态管理 | GameManager, AudioManager, SceneManager |
| 状态机 | 角色行为切换 | PlayerState, EnemyAIState |
| 观察者 (Signal) | 模块解耦 | 战斗事件、UI更新 |
| 策略模式 | 阵营差异 | 科技阵营操作/魔法阵营操作 |
| 对象池 | 频繁创建销毁 | 子弹、伤害数字、掉落物 |
| 组件模式 | 功能组合 | Hitbox/Hurtbox、移动组件 |

### 6. 开发里程碑

按依赖关系排序开发阶段：

**阶段1 - 基础框架**：场景管理、角色控制、受伤判定
**阶段2 - 核心战斗**：战斗系统、怪物AI、经济系统
**阶段3 - 内容系统**：对话系统、背包系统、战斗场景系统
**阶段4 - UI与优化**：UI系统、关卡类型、存档系统
