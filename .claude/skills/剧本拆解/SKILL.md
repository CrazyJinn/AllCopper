# 剧本拆解

将剧本大纲转化为可直接用于开发的详细分场剧本。

## 执行流程

### 阶段1：从 backlog 获取任务

读取 `99_流程管理/backlog.yaml`，找到 `task_id: 剧本拆解` 的条目，获取：
- `inputs`: 输入文件列表
- `outputs`: 预期输出文件列表

若 backlog 中无本任务，说明当前无可执行任务，提示用户使用 `/流程管理` 初始化。

### 阶段2：执行剧本拆解

1. 按 `inputs` 读取输入文件（`00_init/剧本大纲.md`，推荐 `CLAUDE.md` 和 `01_需求文档/角色需求.md`、`01_需求文档/场景需求.md`），检查是否全部存在。缺失则终止并报告
2. **校验场景与角色** - 对比 `01_需求文档/场景需求.md` 和 `01_需求文档/角色需求.md`，识别剧本中出现的未定义场景和角色，记录到未知清单
3. **分析大纲** - 识别幕的划分、场景边界、角色出场、情绪转折，同时追踪每个场景的环境特征（如雪山、沙漠、雨林等）对角色外观的影响
4. **生成提纲** - 创建/更新 `剧本大纲.md`，概括各幕核心内容
5. **拆解分场** - 将概要展开为详细对话和动作
6. **按幕输出** - 为每一幕创建/更新独立文件（第一幕.md、第二幕.md...）
7. **提取表情与变装需求** - 汇总各角色在剧本中出现的表情，以及因场景/状态变化需要的立绘变体（如冬装、雨衣、战斗装等），输出到 `角色立绘表情需求.md`
8. **生成立绘提示词** - 基于表情需求、角色性格和场景变体，为每个角色生成 `立绘提示词.md`（含场景专属变装提示词）
9. 验证 `outputs` 中的所有文件已正确生成

#### 输出目录结构

```
输出目录/
├── 剧本大纲.md          # 各幕内容概览
├── 第一幕.md
├── 第二幕.md
├── ...
├── 角色立绘表情需求.md   # 汇总各角色表情及场景变装需求
└── 立绘提示词/           # 各角色的立绘提示词
    ├── char_001_罗兰.md        # 含基础表情 + 场景变装提示词
    └── char_002_薇.md
```

> 若文件已存在则更新内容。

#### 核心原则

**镜头类型（必需）**：

| 类型 | 标记 | 说明 |
|-----|------|------|
| **立绘对话** | `【立绘对话】` | 显示角色立绘+文字框，暂停游戏，点击继续 |
| **过场动画** | `【过场动画】` | 预制动画片段（短动画/CG），不可交互 |
| **场景对话** | `【场景对话】` | 战斗/探索中的NPC旁白，不暂停游戏，不影响操作 |

**对话编写**：
- 每句对话控制在20字以内（适合游戏阅读）
- 体现角色性格和说话风格
- 避免信息倾泻，通过动作和环境传达信息

**节奏控制**：
- 过场动画：紧凑有力，每段3-5句旁白
- 对话场景：给玩家选择权，2-3轮对话后给选项
- 战斗前：简短铺垫，快速进入战斗

#### 文件命名规则

| 内容 | 文件名 | 说明 |
|-----|-------|------|
| 剧本提纲 | 剧本大纲.md | 各幕内容概览、场景数量、主要角色 |
| 第N幕 | 第N幕.md | 详细分场剧本 |
| 表情需求 | 角色立绘表情需求.md | 各角色表情汇总及场景变装需求 |
| 立绘提示词 | 立绘提示词/char_XXX_角色名.md | 各角色的立绘提示词（含变装） |

#### 角色立绘表情需求格式

```markdown
# 角色立绘表情需求

## 罗兰 (char_001)

### 表情需求

| 表情 | 出现场景 | 优先级 |
|-----|---------|:------:|
| 平静 | 场景1.3, 场景2.1 | 必需 |
| 愤怒 | 场景1.5 | 必需 |

### 场景变装需求

| 变装类型 | 适用场景 | 变装描述 | 优先级 |
|---------|---------|---------|:------:|
| 冬装 | 场景3.1(雪山), 场景3.4(暴风雪) | 厚重防寒大衣，围巾，手套，可见呼吸白雾 | 必需 |
| 战斗负伤 | 场景5.2 | 衣服破损，绷带，血迹 | 可选 |
```

**表情分类**：基础（平静、微笑）、情绪（大笑、愤怒、暴怒、沮丧）、状态（思索、冷漠）

**场景变装规则**：
- 当角色进入特殊环境（雪山、沙漠、雨林、水下等）时，需生成对应变装立绘
- 当角色状态发生变化（受伤、变身、装备更换等）时，需生成对应变装立绘
- 同一角色在同一场景中可能同时需要不同表情×变装的组合

**提取规则**：
- 表情：扫描所有对话识别表情→去重合并→标注优先级
- 变装：扫描场景环境描述→识别环境/状态变化→匹配角色→生成变装需求

#### 未知场景与角色校验规则

- 读取 `01_需求文档/场景需求.md` 中已定义的场景列表，与剧本中出现的场景逐一比对
- 读取 `01_需求文档/角色需求.md` 中已定义的角色列表，与剧本中出场的角色逐一比对
- 未匹配的场景/角色直接写入 feedback.yaml 的 `unable_to_process`，格式：`"未知场景: 冰晶洞窟(第三幕·3.2)、地下暗河(第四幕·1.1)"`

#### 立绘提示词核心原则

- **不描述**：角色外观、服装、配色、艺术风格等（设计图中已有）
- **只描述**：表情变化、身体姿态、手部动作、面对镜头的角度、整体氛围
- **变装描述**：场景专属变装需描述服装/装备的变化部分（如加厚外套、围巾、护目镜等），其余沿用设计图
- 每个提示词至少6个分句，约80-120字

**变装立绘生成规则**：
- 变装立绘以基础表情为模板，追加场景/状态相关的服装描述
- 变装提示词中标注 `【变装：XXX】`，便于识别和批量生成
- 优先为高频场景和关键剧情生成变装立绘

详细格式见 [references/template-立绘提示词.md](references/template-立绘提示词.md)

### 阶段3：写入 feedback 摘要

执行完成后，向 `99_流程管理/feedback.yaml` 追加执行摘要：

```yaml
entries:
  - task_id: 剧本拆解
    skill: 剧本拆解
    executed_at: "<当前时间 ISO格式>"
    processed:              # 已成功完成
      - "生成第一幕剧本"
      - "生成角色立绘表情需求"
      - "生成场景变装需求"
    unprocessed:            # 需后续处理，留在 backlog
      - "第四幕剧本待补充"
    unable_to_process:      # 无法处理，标记 blocked
      - "未知场景: 冰晶洞窟(第三幕·3.2)、地下暗河(第四幕·1.1)"
      - "未知角色: 老猎人(第二幕·2.3, NPC)"
```

**三类摘要说明**：

| 类型 | 含义 | 后续动作 |
|------|------|----------|
| processed | 已成功完成 | 节点标记 completed |
| unprocessed | 需要后续处理 | 保留在 backlog |
| unable_to_process | 无法处理，需人工介入 | 节点标记 blocked |
