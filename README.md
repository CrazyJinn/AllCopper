## 变更管理流程

当需求发生变化时，按以下流程处理：

```
1. 记录变更 → 2. 影响分析 → 3. 发送通知 → 4. 执行更新 → 5. 确认完成
```

### 触发条件

| 变更来源 | 影响范围 |
|---------|---------|
| 世界观.md 修改 | 需求分析、角色设计、场景设计、剧本拆解 |
| 设定集.md 修改 | 需求分析、角色设计、场景设计 |
| 剧本大纲.md 修改 | 剧本拆解、分镜设计、音频实现 |
| 需求文档修改 | 对应的下游设计/实现环节 |

### 变更记录格式

```markdown
## [日期] 变更标题

### 变更内容
- 具体修改了什么

### 影响分析
- 受影响的文档/环节列表

### 更新状态
| 文档 | 状态 | 更新人 |
|-----|------|-------|
| xxx | 待更新/已更新 | - |
```
